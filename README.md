# Project Station

TypeScript 全栈个人项目工作空间：项目列表、独立 Timing 页面、分层甘特图、工作日排期、任务附件、经验手记和管理后台。需要 Node.js 24+，服务端使用内置 SQLite；Excel 原模板读写及 PDF 导出使用锁文件中的运行依赖。

## 本地运行

```sh
pnpm install --frozen-lockfile
npm start
```

Windows 可运行 `./start.ps1`。脚本优先使用系统 Node.js，其次使用本机 Codex 提供的 Node.js。打开 http://127.0.0.1:3000 。

已有管理员账号及密码在迁移后继续有效。全新数据目录首次启动必须通过 `ADMIN_PASSWORD` 设置 10–1024 位初始密码，创建唯一管理员 `admin`，密码不输出到日志。已有账号不会被这个环境变量覆盖。请通过本机安全环境设置密码，不写入仓库。会话有效期 24 小时，服务重启后需重新登录。

## 项目与 Timing

新建项目只填写名称、分类、负责人、计划起止日期和简介。创建后跳转到 `/projects/:id/timing`，此地址可以直接打开或刷新。

每个新项目默认创建八个一级汇总阶段：

1. Customer Mile Stone
2. RFQ Quotation
3. Project kick off
4. CV
5. DV
6. PV
7. PPAP
8. SOP

点击阶段旁的 `＋` 添加子任务，或点击工具栏「新建任务」。任务名称可打开详情面板，编辑名称、类型、父目录、负责人、日期、工期、完成度、前置任务和备注。表格中的负责人、日期、工期、完成度支持直接修改。可添加多层子任务；添加子任务后，普通任务变为汇总阶段。带有依赖关系的普通任务需要先清除相关依赖，才能转换为父任务。里程碑不包含子任务。

甘特图支持日/周/月视图、前后翻页、定位今天、阶段折叠与展开。表格和时间轴的纵向滚动同步，各自可横向滚动。小屏幕保留左右分栏，通过横向滚动查看完整列；精细排期更适合桌面。

## 排期规则

Timing 提供基线、V 序列和最终版本的保存及比较。D8 起，每项目使用一份服务器共享草稿和单人编辑占用；自动保存和确认导入只更新草稿，采用后才更新执行计划，内容变化时自动生成 V 版本。历史版本支持软删除与撤销，快照内容保持只读。[D8 记录](docs/d8-shared-draft.md)说明租约、采用、归档和附件保留规则。

通过 **导出 / 导入** 可选择服务器执行计划或保留版本导出 Excel/PDF/Project XML，并上传 Excel 或 Microsoft Project XML，经匹配、排期预览后确认导入共享草稿。Excel 保留三级/100 项原模板计算能力；Project XML（MSPDI）支持 20 级/1000 项，不支持原生 `.mpp`。格式限制见 [Excel/PDF 记录](docs/batch-d2-d3-validation.md)及 [D9 XML 记录](docs/batch-d9-validation.md)；Microsoft Project 桌面互操作仍待验收。

本地未提交输入、服务器共享草稿、正式执行计划和编辑租约分别管理。保存失败会阻止普通退出、历史切换及 Escape 关闭；失去租约后保留输入，重新授权、取得新租约并成功读取最新数据后，由用户比较并选择恢复或放弃。恢复只填回本地，须手动保存，不自动重放旧请求。恢复副本使用稳定用户 UUID/项目隔离，尽力保存在当前标签页 sessionStorage（存储受阻时只保留内存）；刷新可比较恢复，关闭标签页或清理浏览器存储后不承诺保留。共享草稿不是此本地恢复副本。

采用响应丢失表示结果未知，页面要求刷新核对执行计划；已收到写入成功而重读失败则明确显示“写入已确认”。两种情况均不自动重提。后台回执使同一确认/采用重试不重复业务效果。

- 工作日为周一至周五，暂不配置节假日。日期支持 2000–2100 年，普通任务工期 1–2600 个工作日。
- 普通任务的开始、工期和结束日期互相关联。周末开始日期自动移至下一个工作日。
- 拖动任务条移动开始日期并保留工期；拖动两端改变工期。里程碑工期为 0，开始和结束同日。
- 前置关系为 FS（完成后开始），可指定多个前置任务。后续任务最早从前置任务结束后的工作日开始；不满足条件时自动顺延，可连锁传播。
- 前置任务提前时，后续任务保留原日期，不主动提前。依赖设置在普通任务或里程碑上，汇总阶段不参与依赖。禁止循环依赖和跨项目依赖。
- 汇总阶段日期覆盖已排期子任务；完成度按叶子任务工期加权，里程碑权重为 1。项目建立任务后，整体完成度也由叶子任务汇总。
- 没有日期的任务显示为「未排期」。排期保存采用事务和版本号：遇到其他成员的并发修改时返回冲突提示，避免覆盖其更改。
- 本版不包含关键路径、成本/资源负荷、法定节假日日历或 `.mpp` 导入导出。

## 权限与附件

单一组织，多个项目能力组。admin 管理全部资源；项目 Manager 可管理该项目成员/可见性并创建项目。Editor、Engineering、Viewer 和 admin 自建能力组分别控制 Timing、附件、项目知识等能力，全站 viewer 保持只读上限。Engineering 默认可上传附件、创建编辑 Lesson Learn，不能修改 Timing 或删除附件/知识。

项目卡片和全站 Lesson Learn 默认公开；Timing、任务备注、附件和关联项目文章默认仅有效登录账号可读。管理者可逐项目将卡片、Timing 和项目文章收紧到成员组权限。成员清单仅授权项目成员可读，全站账号仅 admin 可读。项目写入需明确成员能力；移出成员与停用账号是不同操作。旧项目不会自动给所有旧账号分配成员。

用户使用不可重用 UUID，登录名/显示名与身份分离。删除重建同名账号不继承权限；改密、重置、停用和全站角色变化使旧会话失效。管理工作台提供自助改密、管理员账号恢复与组管理，Timing 提供成员及可见性入口。

任务附件单文件最大 20 MB；文件通过最新权限检查下载，不作为公开静态资源。上传与删除按独立能力控制，删除使用 B 的持久任务和隔离机制。文章创建可选项目，已有关联不可换项目；有关联文章时删除项目会提示先处理文章。

权限矩阵、稳定身份、旧历史映射限制、TRUSTED_PROXIES 配置/限流阈值、迁移及回退、受控离线恢复见 [C 运维说明](docs/batch-c-operations.md)，实际证据见 [C 验证记录](docs/batch-c-validation.md)。阶段级编辑授权留后续；本地验收不表示可生产上线。

## 数据迁移与备份

正式数据位于 `data/`（或 `DATA_DIR` 指定的绝对路径）：

```text
data/
  project-station.sqlite         SQLite 数据库
  project-station.sqlite-wal     SQLite 运行时日志（可能存在）
  project-station.sqlite-shm     SQLite 运行时文件（可能存在）
  uploads/                      附件文件
  store.json                    保留的旧版数据，不再写入
  store.pre-sqlite-*.json        首次迁移前的原始备份
```

首次启动新版本时，如发现旧 `store.json`，会先备份，再在事务中迁移账号、项目、文章和网站设置。网站名称更新为 Project Station，已有项目补齐八阶段空模板。迁移标记保存在数据库中，后续启动不会重复迁移或重建被删除的阶段。

备份须先停写、停止服务，再使用纳入 Git 的 `scripts/data-maintenance.ts`：独占目录锁、checkpoint WAL，生成包含数据库、uploads 和隔离区的一致快照及校验清单；恢复只写新目录。命令、失败处理和配套代码恢复约束见 [B 运维说明](docs/batch-b-operations.md)，实际证据见 [B 验证记录](docs/batch-b-validation.md)。不要只复制运行中的 SQLite 主文件。

E 新增迁移9（历史元数据分页索引及内容指纹侧表）与10（项目/文章摘要投影），不改已发布迁移1–8。旧代码会拒绝新迁移库，回退必须恢复迁移前配套代码及完整数据库/附件快照。D9实际代码生成的合成迁移8数据、升级到10、共享草稿/租约/回执/软删除/归档附件字节恢复见 [E 验证](docs/batch-e-validation.md)。

## 分页与文件资源配置

首页返回项目/文章摘要，默认每类24项，正文按资源ID读取；搜索和筛选在服务端作用于全部授权摘要。历史默认50条，通过“加载更多”访问后续页，比较及导出选择同样支持后续版本。分页/统计先过滤当前权限，不缓存跨请求的授权。接口参数及游标语义见 [写入与查询契约](docs/write-contract.md)。

HTTP文件计算使用Node worker池，SQLite与提交留在主线程。默认2个活跃任务、8个等待任务、总期限10秒（包含读取请求体、排队和启动）；上传8 MiB、任务/结果各32 MiB、队列载荷合计64 MiB，每worker old generation上限256 MiB。V8 heap上限不等于全进程RSS硬限制，部署前应实测目标机器。

| 环境变量 | 默认 | 允许值 |
| --- | ---: | --- |
| `FILE_WORKERS` | 2 | 1–4 |
| `FILE_QUEUE` | 8 | 0–16 |
| `FILE_TIMEOUT_MS` | 10000 | 100–20000 |

非法配置启动失败；字节和heap限制不能用环境放大。队列满429、超限413、冲突/过期409、处理故障/停止503、超时504有明确反馈；取消不会自动重试，确认响应丢失需核对草稿。停止服务会拒绝队列并回收worker。[E-B验证](docs/batch-e-b-validation.md)记录配置、最终检查与30轮五文件并发证据。

## 部署

仓库中截至 D9 的上线版本、数据保留检查及恢复点见 [2026-11-03 正式部署记录](docs/production-deployment-d9-2026-11-03.md)。记录中的运行代码为 `0b3f05f`；E 是本地实现与验收，本任务没有重新部署或巡检生产。

使用支持 Node.js 24+ 和持久磁盘的服务器，运行 `npm start`。通过 `PORT` 指定端口，通过 `DATA_DIR` 指定数据库与附件目录。服务监听 `127.0.0.1`，可在同机通过 Nginx/Caddy 反向代理并启用 HTTPS；生产环境设置 `COOKIE_SECURE=1`，反向代理需转发原始 Host，并允许大于 20 MB 的请求体。

当前适合单进程部署；多实例应迁移为共享数据库、附件和会话存储。基础 SEO 提供标题、描述、Open Graph 与 robots.txt；私有 Timing 页面不供搜索引擎抓取。

## 写入版本与工程检查

项目和文章的更新、删除需要资源版本；项目删除同时检查任务版本。任务派生进度不由项目表单写回。数据库通过编号迁移升级，旧 SQLite 和 JSON 导入继续支持。接口、草稿冲突处理、迁移与代码/数据回退限制见 [写入契约](docs/write-contract.md)。

统一验证入口为 `pnpm check`（或 `node --experimental-strip-types scripts/check.ts`），GitHub CI 使用相同入口。

A 批次的实际检查、浏览器场景与未执行范围见 [实施验证记录](docs/batch-a-validation.md)。
