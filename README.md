# Project Station

TypeScript 全栈个人项目工作空间：项目列表、独立 Timing 页面、分层甘特图、工作日排期、任务附件、经验手记和管理后台。需要 Node.js 24+，服务端使用内置 SQLite；第三方包仅用于开发时的类型检查。

## 本地运行

```sh
npm start
```

Windows 可运行 `./start.ps1`。脚本优先使用系统 Node.js，其次使用本机 Codex 提供的 Node.js。打开 http://127.0.0.1:3000 。

已有管理员账号及密码在迁移后继续有效。全新数据目录首次启动会创建唯一管理员 `admin`，随机密码输出到启动终端；也可在首次启动前通过 `ADMIN_PASSWORD` 设置密码。已有账号不会被这个环境变量覆盖。会话有效期 24 小时，服务重启后需重新登录。

## 项目与 Timing

新建项目只填写名称、分类、负责人、计划起止日期和简介。创建后跳转到 `/projects/:id/timing`，此地址可以直接打开或刷新。

每个新项目默认创建八个一级汇总阶段：

1. Customer Mile Stone
2. RFQ Quotation
3. Project kick off
4. CV
5. DV
6. PV
7. PPAP
8. SOP

点击阶段旁的 `＋` 添加子任务，或点击工具栏「新建任务」。任务名称可打开详情面板，编辑名称、类型、父目录、负责人、日期、工期、完成度、前置任务和备注。表格中的负责人、日期、工期、完成度支持直接修改。可添加多层子任务；添加子任务后，普通任务变为汇总阶段。带有依赖关系的普通任务需要先清除相关依赖，才能转换为父任务。里程碑不包含子任务。

甘特图支持日/周/月视图、前后翻页、定位今天、阶段折叠与展开。表格和时间轴的纵向滚动同步，各自可横向滚动。小屏幕保留左右分栏，通过横向滚动查看完整列；精细排期更适合桌面。

## 排期规则

- 工作日为周一至周五，暂不配置节假日。日期支持 2000–2100 年，普通任务工期 1–2600 个工作日。
- 普通任务的开始、工期和结束日期互相关联。周末开始日期自动移至下一个工作日。
- 拖动任务条移动开始日期并保留工期；拖动两端改变工期。里程碑工期为 0，开始和结束同日。
- 前置关系为 FS（完成后开始），可指定多个前置任务。后续任务最早从前置任务结束后的工作日开始；不满足条件时自动顺延，可连锁传播。
- 前置任务提前时，后续任务保留原日期，不主动提前。依赖设置在普通任务或里程碑上，汇总阶段不参与依赖。禁止循环依赖和跨项目依赖。
- 汇总阶段日期覆盖已排期子任务；完成度按叶子任务工期加权，里程碑权重为 1。项目建立任务后，整体完成度也由叶子任务汇总。
- 没有日期的任务显示为「未排期」。排期保存采用事务和版本号：遇到其他成员的并发修改时返回冲突提示，避免覆盖其更改。
- 本版不包含关键路径、成本/资源负荷、法定节假日日历或 `.mpp` 导入导出。

## 权限与附件

| 功能 | 访客 | 只读成员 | 编辑者 | 管理员 |
| --- | --- | --- | --- | --- |
| 项目列表、经验手记、PM 与团队介绍 | ✓ | ✓ | ✓ | ✓ |
| 项目 Timing、任务详情、附件下载 | — | ✓ | ✓ | ✓ |
| 项目、任务、排期、附件和文章管理 | — | — | ✓ | ✓ |
| 网站配置、成员管理 | — | — | — | ✓ |

项目基本信息列表仍公开；任务、排期与附件仅登录成员可访问。所有登录成员可访问所有项目，本版不按项目分配阅读权限。

任务详情面板支持多文件上传、下载和删除。单文件最大 20 MB，空文件会被拒绝。文件以随机标识存储，原文件名仅作显示与下载使用。附件通过校验登录的下载接口提供，不作为公开静态资源。删除任务或项目时会删除关联附件；删除阶段包含其全部后代任务。

## 数据迁移与备份

正式数据位于 `data/`（或 `DATA_DIR` 指定的绝对路径）：

```text
data/
  project-station.sqlite         SQLite 数据库
  project-station.sqlite-wal     SQLite 运行时日志（可能存在）
  project-station.sqlite-shm     SQLite 运行时文件（可能存在）
  uploads/                      附件文件
  store.json                    保留的旧版数据，不再写入
  store.pre-sqlite-*.json        首次迁移前的原始备份
```

首次启动新版本时，如发现旧 `store.json`，会先备份，再在事务中迁移账号、项目、文章和网站设置。网站名称更新为 Project Station，已有项目补齐八阶段空模板。迁移标记保存在数据库中，后续启动不会重复迁移或重建被删除的阶段。

备份时先停止服务，再复制 SQLite 文件和 `uploads/`；如仍存在 `-wal` 和 `-shm`，一并保留。恢复时使用同一套数据库和附件。请不要只复制运行中的 SQLite 主文件。

## 开发验证

```sh
pnpm install --frozen-lockfile
npm run typecheck
npm test
```

类型检查覆盖前后端 TypeScript。测试在系统临时目录运行，涵盖工作日与里程碑、依赖顺延、循环拦截、汇总、事务回滚、旧数据迁移、角色权限、附件上传下载与超限限制、版本冲突、重启持久化、密码和会话。

`scripts/preview-fixture.ts` 可生成独立的浏览器验证数据，固定写入 `data/preview-fixture/`，不修改正式数据库。该脚本中的账号仅用于隔离验证环境，不用于部署。

## 部署

使用支持 Node.js 24+ 和持久磁盘的服务器，运行 `npm start`。通过 `PORT` 指定端口，通过 `DATA_DIR` 指定数据库与附件目录。服务监听 `127.0.0.1`，可在同机通过 Nginx/Caddy 反向代理并启用 HTTPS；生产环境设置 `COOKIE_SECURE=1`，反向代理需转发原始 Host，并允许大于 20 MB 的请求体。

当前适合单进程部署；多实例应迁移为共享数据库、附件和会话存储。基础 SEO 提供标题、描述、Open Graph 与 robots.txt；私有 Timing 页面不供搜索引擎抓取。

## 写入版本与工程检查

项目和文章的更新、删除需要资源版本；项目删除同时检查任务版本。任务派生进度不由项目表单写回。数据库通过编号迁移升级，旧 SQLite 和 JSON 导入继续支持。接口、草稿冲突处理、迁移与代码/数据回退限制见 [写入契约](docs/write-contract.md)。

统一验证入口为 `pnpm check`（或 `node --experimental-strip-types scripts/check.ts`），GitHub CI 使用相同入口。

A 批次的实际检查、浏览器场景与未执行范围见 [实施验证记录](docs/batch-a-validation.md)。
