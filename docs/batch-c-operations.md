# Batch C：身份、能力组与项目访问

本批仅实现、验证本地单进程应用。生产切换、正式库迁移、停服、备份调度与发布需要另行授权。

## 已确认业务规则

单一组织，多个项目组。admin 管理全站全部资源；项目 manager 也可创建项目。admin 可创建、修改能力组；项目管理者为具体项目分配成员和能力组、设置可见范围。组是能力组合，不是隔离组织或全库成员标签。每个账号在每个项目有一条成员关系，可跨项目使用不同组。全站知识能力组另在账号中设置。

预置组能力如下，admin 可继续创建自定义组。全站 viewer 始终只读，即使分到 Manager 也不会获得写入能力；未知全站角色、无效身份、停用账号拒绝认证。自定义组中未知能力不被接受。

| 项目能力 | Manager | Editor | Engineering | Viewer |
| --- | --- | --- | --- | --- |
| 读取 Timing / 项目文章、查看项目成员 | ✓ | ✓ | ✓ | ✓ |
| 修改项目基础信息、Timing / 任务 | ✓ | ✓ | — | — |
| 上传附件 | ✓ | ✓ | ✓ | — |
| 删除附件 | ✓ | ✓ | — | — |
| 创建、编辑 Lesson Learn | ✓ | ✓ | ✓ | — |
| 删除 Lesson Learn | ✓ | ✓ | — | — |
| 管理项目成员和可见范围、删除项目 | ✓ | — | — | — |
| 创建新项目 | ✓ | — | — | — |

Manager 在任一项目的成员关系可授予创建项目能力；账号的全站组也可被 admin 配置此能力。创建项目者在新项目登记为 Manager，和项目、八阶段模板、成功审计同事务提交。admin 不依赖成员关系访问。阶段级编辑授权是后续目标，本批没有声称具备。

## 默认公开与收紧

- 所有新旧项目默认卡片公开，Timing / 任务 / 附件及项目文章默认仅登录的有效账号可读。访客只能看卡片和全站知识，不能读取 Timing、备注或附件。访客卡片只含 ID、标题、简介、分类、负责人文本、日期、状态、进度及资源版本；不含项目正文、任务、附件和成员。
- 管理者可独立将卡片改为仅成员，将 Timing 和项目文章改为按成员组的 timingRead / lessonsRead 能力读取。选择“登录可读”时，不要求该账号是项目成员；移出成员仍立即撤销项目写入和成员清单权限，但在此公开范围下仍可读取。这是已确认的默认公开规则。需要完整撤销读取时，使用成员范围。
- 旧 Lesson Learn 保留为全站公开知识，包括现有 Markdown 下载；新文章创建时可选择项目。项目文章读取遵守该项目 lessons 范围，不从请求声称的 projectId 推定已有文章归属。文章创建后不允许换项目。关联文章未处理时项目删除返回 409，防止丢失/错误重归属知识。
- `/api/data` 先过滤项目和文章；Timing 只提供该项目授权成员，不返回全站用户。只有 admin 可读全站账号。项目管理者可从候选接口读取用于分配成员的最少账号资料；其他成员只能读所在项目已分配成员。未授权 ID 返回统一不可见/不存在错误，响应 no-store。
- API 是权限边界，按钮能力仅用于体验。`lib/policy.ts` 的 requireRead/articleRead/attachmentProject/taskProject 是后续导出等读取入口必须复用的边界，本批未新增 D 的导出。

## 稳定身份与会话

迁移 003 增加 identities。每个账号产生独立随机 UUID；users.id 保留旧存储/登录键兼容，绝不用于授权关系。HTTP 账号 id、会话、成员及新审计 actor_uid、附件 uploaded_uid 使用 UUID。登录名、显示名可变，原始登录证据保留；身份 UUID 不更新、不复用。删除账号会退休登记并移除成员关系，不删除身份墓碑。重建同名账号得到新 UUID，不继承旧会话、成员或历史。

会话存内存，24h 到期，重启需重新登录；同时有最多 10,000 条内存会话。会话携带 UUID 和 authEpoch。停用、重新启用、删除、全站角色/全站组/登录名变化、改密和管理员重置使旧会话失效；自助改密包括发起会话。仅修改显示名不改变身份。项目移出/降权、能力组修改即时按当前关系重检，不等同停用全站账号；重新加入只获得当次明确组，不恢复旧权限。

最后一个 active 且有有效凭据的 admin 不允许停用、删除或降权。正常恢复由另一个 admin 在“管理工作台→管理账号→重置密码”操作；如账号停用，还需显式重新启用。重置不展示旧密码，不返回新密码或会话。账号、成员、组、可见性、密码的成功历史与变更同事务，密码审计仅保留类型、身份和时间等元信息。

JSON 请求体读完后重读会话和账号，再同步检查 policy 并进入业务 SQLite 事务；单进程事件循环不在检查和写入之间 await。上传在收完字节、sync/rename 后，在附件登记事务内同步重读身份和当前项目能力。撤权后的暂存字节进入 B 的 file_jobs/隔离清理，不补成功附件或业务审计。下载在异步文件打开后、发送响应头前重检当前权限；已开始发送不强制中断，不声称收回已发送字节。

## 旧数据映射与诊断

迁移 003、004 沿用编号事务机制，不改 001/002。SQLite B 夹具见 tests/fixtures/b-schema.sql。旧用户各生成 UUID；旧密码、姓名、项目/文章/任务/依赖、附件字节/上传证据、审计、file_jobs、version/revision 保留。旧项目不批量加入用户，不按 owner 姓名/登录名猜经理。旧项目的负责人文本原样保留。

旧 audit actor_id 和附件 uploaded_by 只是原始字符串证据；新增 actor_uid/uploaded_uid 为 NULL，不因当前有同名账号而补关联。新成功审计使用稳定身份并保存显示名快照。没有补造迁移前历史。可在停写副本执行：

```sh
node --experimental-strip-types scripts/data-maintenance.ts identity-report --data /absolute/copied-data --offline-confirmed yes
```

报告列出待分配项目、未确认上传和审计数量、未知角色/状态账号。由 admin 按 UUID 显式分配成员；历史确认需独立证据，不提供按字符串自动关联功能。无可用 admin、损坏身份/策略、无法识别的迁移在恢复校验中失败，不回退为全员访问。

## 可信代理与登录保护

`TRUSTED_PROXIES` 默认为空；精确 IP 列表如 `127.0.0.1,::1`，不接受 CIDR/域名/端口。只有连接对端可信才解析 X-Forwarded-For，从右向左剥离可信节点，在第一个不可信节点停止。IPv4-mapped IPv6 规范化；非法、空、多值头或超过 16 跳回退连接地址。忽略 X-Real-IP/Forwarded。边缘代理须覆盖外来伪造头或正确追加并保护可信链。

失败窗口 15min；账号+来源/账号/来源/整体上限 10/40/400/2000。组合从第 5 次失败开始 1、2、4、8、16、32、60s 退避，达到阈值等待窗口到期。成功不抹攻击记录；最多 10,000 个哈希计数键，满载拒绝新键而不驱逐活跃键，请求时清理过期；重启清空。限流响应不区分账号是否存在。此为单进程有界实现，不是分布式容量防护。

部署须实测实际代理、Host、HTTPS、COOKIE_SECURE=1、网络边界和客户端地址；本机反代测试不是生产配置验收。

## 无管理员访问时的受控离线恢复

先由有本机数据目录权限的运维人员停止全部写入，取得并保护成套故障快照，核对配套代码/迁移。在副本验证恢复流程。没有 HTTP 免认证入口或固定万能密码。脚本不初始化目录，须已初始化的 C/004 库，独占目录锁，明确声明无法使用任何管理员。密钥式新密码仅从安全环境 RECOVERY_PASSWORD 读取，不作为命令参数或日志输出：

```sh
node --experimental-strip-types scripts/recover-admin.ts --data /absolute/copied-data --login admin --offline-confirmed yes --no-admin-access yes
```

可恢复已有 admin 的凭据/active 状态；或选择全新登录名创建独立 admin，不能把普通账号隐式提权。已有身份不变、epoch 增加，新身份不继承旧成员；恢复操作审计为 system:offline-recovery。运行后清除该环境变量，重启并登录，再核验权限和审计；按既定负责人登记操作。目录权限是该离线流程的认证边界。生产上执行该流程仍需单独授权。

## 快照与回退

C 快照清单逐表纳入 identities、permission_groups、project_members、project_access 和新增关联列。除了 SQLite 完整性/外键、附件大小/摘要，还检查身份双向映射、退休登记、有效 admin、项目策略完整性及组能力。审计和 file_jobs 沿用 B 的表摘要；隔离文件一起备份。恢复只写新目录，服务启动后重新登录并实测权限、成员、项目文章和附件。

C/003+004 数据不能交给 B 代码使用。只 git revert 无法回收已写身份/权限语义；故障时停写，恢复与快照配套的代码和数据库/uploads/隔离区，或使用另行验证的兼容方案。快照后的写入不保证保留。授权异常应拒绝或进入维护，禁止恢复“全员访问”。B 已确认目标和全部生产前置条件保持有效。
