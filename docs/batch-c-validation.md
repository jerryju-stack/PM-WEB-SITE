## 已实施的独立边界

1. `lib/login-security.ts` 提供精确地址可信代理解析；默认不信任任何代理。仅可信连接可使用 X-Forwarded-For，从右向左剥离显式可信地址，在第一个不可信地址停止；IPv4-mapped IPv6 规范化。端口、空值、非法地址、多值头和超过 16 跳的链回退连接地址。忽略 Forwarded/X-Real-IP。不支持 CIDR，非法 TRUSTED_PROXIES 导致启动失败。
2. 登录失败采用账号+来源、账号、来源和整体四个窗口。15 分钟固定窗口阈值分别为 10/40/400/2000；组合失败第 5 次开始退避 1、2、4、8、16、32、60 秒，组合达到 10 次或其他桶达到阈值后等待窗口到期。成功不清空攻击计数，不暴露账号存在性。账号键 SHA-256，输入截断，最多 10,000 项；满载时拒绝新键，不驱逐活跃记录；请求时清理过期项，进程重启清空全部计数。此实现是单进程失败尝试保护，不承诺抵御分布式容量攻击。
3. JSON 请求体读完后重新解析当前会话和账号；允许编辑角色明确列举 admin/editor，未知角色拒绝。后续授权到业务同步事务之间没有 await。附件接收和 rename 后，在登记事务内执行同步授权回调，撤权拒绝时复用 B file_jobs 和隔离清理，不创建成功业务/审计记录。该机制待 C policy 建立后接入账号状态/项目成员与角色。
4. 附件下载异步打开文件后、发响应头前再次检查当前会话/账号；当前仍是 B 的全站登录权限，项目边界尚未完成。开始发送后不宣称收回已发送字节。
