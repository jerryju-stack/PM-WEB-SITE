# Project Station 浅色与深色主题实施计划

以财务总览作为浅色样板，再推广到全站。用户可以在同一页切换主题，正在阅读的行、填写的内容和选中的项目都留在原处。两个主题共用字体、间距和信息层级。

## 设计依据与版本范围

- 2026-11-19 核对了正式站公开的 `/finance` 页面外壳。它固定声明浏览器主题色 `#141518`，依次加载 `styles.css`、`timing.css`、`finance.css`。下文的组件与交互分析来自当前仓库。
- 参考附件《财务工作台审核报告与效果图》第 4 页的总览、第 5 页的年度销量表和第 6 页的采购明细。总览用一条连续指标带建立主次，数字比标签重，单位与期间另起一行。明细页用淡色表头、细分隔线、左侧行名和右对齐数值帮助读者横向比较。报告页眉的“设计审核”和页脚的审核说明属于文档版面。
- 本版范围为主题偏好、视觉层级及现有界面的适配。财务口径、示例金额、部门功能建议以及旧路线图中的语言切换、8D 和账号跨设备同步各自独立排期。实施时以现有页面数据、界面语言和权限为准。
- 建议首次访问跟随系统，顶栏提供“跟随系统 / 浅色 / 深色”。偏好保存在当前浏览器的同一站点，访客和登录用户都能使用。用户明确选择浅色或深色后优先采用该选择。重新选择跟随系统后立即响应系统变化。

## 可用于验收的视觉定值

颜色取自参考页。字号、行高和留白是针对实际网页的实施目标。两个主题使用相同的尺寸。下表为默认缩放下的 CSS 像素，实施时用可随浏览器字号缩放的单位表达文字层级。

| 元素 | 实施目标 | 检查方式 |
| --- | --- | --- |
| 浅色底与面板 | 页底 `#F5F6F8`，白色侧栏、顶栏与面板，细分隔线 `#DCE0E8` | 靠面板边界和留白区分区域，键盘焦点使用单独的高对比描边 |
| 文字与强调 | 主文字 `#191C2B`，说明 `#555C70`，链接与主操作以 `#5743A1` 为起点，选中项用淡紫底。现金流柱可用 `#14796C` | 状态同时有文字或形状。深色以现站底色 `#141518`、面板 `#1D1E23`、主文字 `#ECEDEF` 为起点，再校验各个前景与背景组合 |
| 页标题与一级指标 | 桌面页标题 32/40、字重 700，手机 26/34。关键数值 26/34、字重 700，长币值可独占一行 | 先看到标题与数值，再读到期间、币种和单位。日期、金额及百分比用等宽数字 |
| 区块、正文、辅助信息 | 区块标题 18/26、字重 600。正文和控件 15/24、字重 400–500。表格正文 14/22、表头 13/20、字重 600。单位和说明 13/20、字重 400 | 用字重提示标题、关键值与合计。连续段落保持正常字重，密集表格保证行与列的对应关系 |
| 留白与对齐 | 标签到数值 4–8，组内 8–12，卡片内边距 16–20，主要区块间距 24，桌面内容边距 24–32，手机 16。面板圆角 8 | 同类标题与数据列从同一条线开始。普通数据表默认行高约 40，可随内容增长。Timing 单独保留其几何尺寸 |
| 宽表与窄屏 | 宽屏将同组指标放在一条带内，窄屏按实际数值长度折成两列或一列。数值靠右，行名靠左，长文字可换行 | 390px 下单位、负号和小数完整。宽表在组件内横向滚动，页面主体没有横向滚动条 |

## 如何交给 Codex

在本仓库中按 01 → 07 顺序执行。每次可以只复制对应代码块到一个新对话。每段第一句都指向本计划，以便新对话取得设计定值和共同约束。第 04 步是判断视觉方向的节点。第 07 步产出可发布版本，第 08 步供决定发布时单独下达。

**各步共同约束**　先读 `AGENTS.md` 和本计划，核对前一步交付与工作树。使用现有 TypeScript、CSS、字体栈和测试工具，采用本地隔离样例。主题仅影响展示。切换动作只更新浏览器本地偏好、主题控件和已挂载的视觉组件。现有未提交修改由原作者保留。每个重要阶段完成并验证后，仅提交该阶段的文件。反馈变更范围、实际运行的检查及结果、代表性截图路径、提交号和仍待验证项。若当前阶段没有产生变更，报告已有证据。

### 01　建立基线与设计规范

**交付**　更新 `docs/design-system.md`，归档一组可以用相同路由、数据、视口复拍的现状截图。优先选择已有脱敏案例，另取一个少数据或无数据状态。

```text
在 Project Station 仓库执行 docs/site-theme-rollout-plan.md 第 01 步，遵守共同约束。阅读 src/index.html、server.ts、src/styles.css、src/finance.css、src/timing.css、docs/design-system.md 和现有浏览器验收脚本。对照参考 PDF 第 4–6 页及本计划定值，把浅深色映射、字体、字重、留白和状态写入现有设计规范。列出普通站点外壳、财务、Timing、弹窗和图表各自的入口，以及固定色、内联色和强制 dark 的位置。在隔离预览用相同数据拍 1440×960 与 390×844 的现状，至少覆盖项目概览、财务总览、商务宽表、Timing 任务抽屉。记录基线提交、路由、视口和复拍方法。交付规范、差异清单和截图索引，提交文档。
```

### 02　建立两套颜色与一套排版

**交付**　根元素可切换两套主题，页面、浮层和原生控件继承同一组变量。开发者能在本地先验证根元素属性的效果。

```text
在 Project Station 仓库执行 docs/site-theme-rollout-plan.md 第 02 步，遵守共同约束并读取第 01 步规范。以 src/styles.css 现有 --ds-* 为基础，把颜色绑定到 html 根元素的 data-theme="light" 或 "dark"。处理旧 :root 浅色底、body 工作区深色变量的层叠，确保 #app、#modal、#toast 和原生表单继承生效。补齐主按钮前景、焦点、边框、选中、成功、警告、危险、图表及遮罩所需的语义色。共用一套字号、行高、字重和间距。为未设属性的页面提供系统配色回退。保留现有样式加载顺序，新增静态文件时同步核对 server.ts 的服务映射。在本地改变根属性，检查两套背景、正文、按钮、输入和弹窗的计算样式，检查普通文本对比度达到 4.5:1。提交主题基础。
```

### 03　实现切换、记忆与首屏

**交付**　普通页面、财务和 Timing 都能从顶栏选择主题，深链接、刷新和系统改色得到同样的结果。

```text
在 Project Station 仓库执行 docs/site-theme-rollout-plan.md 第 03 步，遵守共同约束。在 src/app.ts 的共享顶栏与 src/timing.ts 的独立 station-header 复用一个有可见标签、可用键盘操作的“外观”控件。提供跟随系统、浅色、深色，首次跟随系统。区分“用户偏好”和“当前生效主题”，用一个带站点前缀的 localStorage 键保存偏好。未知值或存储被禁用时回退，可在本页继续切换。仅跟随模式响应 prefers-color-scheme 的变化，同源其他标签页同步选择。根据 server.ts 的 script-src 'self'，在 src/index.html 的样式表之前加载小型同源初始化脚本，并登记静态路由。在首次绘制前设置根属性、color-scheme 和 meta theme-color。切换只更新必要节点，不触发整页 render、数据请求或表单提交。验证冷启动深链接与慢网刷新时的首帧、手动覆盖、系统变化、跨页、跨标签、访客及手机操作。提交主题交互。
```

### 04　先完成财务样板，再覆盖十个业务板块

**交付**　用同一份脱敏数据并排比较财务总览浅色、深色与参考图。用商务或 BOM 页验证实际宽表。样板通过本节标准后，再套用到其余财务页面。

```text
在 Project Station 仓库执行 docs/site-theme-rollout-plan.md 第 04 步，遵守共同约束。使用正式财务渲染路径，从 src/finance.css、src/finance.ts、src/finance-view.ts 和 src/finance-business-view.ts 定位组件。先做财务总览与商务宽表。总览按“页标题和期间 → 已有核心指标 → 图表与待处理事项 → 产品明细”组织。指标共用外框和内部分隔，标签、数值、单位分级，按实际可见指标数和宽度排布。表中行名靠左、金额和百分比靠右，普通行常规字重，链接或合计适度加粗。在 finance-view.ts 的 cashChart 中让已打开的 Canvas 在主题改变时立即按新色重绘，保留数据与图例，卸载时清理监听。用相同数据拍桌面两种主题及手机截图，与 PDF 第 4、5 页核对。再覆盖 /finance 入口、项目财务总览、十个业务板块、设备下钻、筛选、更多设置与空状态。切换前后比对币种、数值、版本、展开状态和当前 URL。已有业务计算及权限测试继续通过。提交财务样板和覆盖结果。
```

### 05　把样板推广到站点公共页面

**交付**　项目、知识、团队、关于、管理和登录沿用同一排版层级。长文阅读、密集表单和手机操作各自有合适的留白。

```text
在 Project Station 仓库执行 docs/site-theme-rollout-plan.md 第 05 步，遵守共同约束。检查 src/app.ts、src/access-ui.ts 和 src/styles.css。迁移项目概览的导航、统计与项目卡，Lesson Learn 列表、文章阅读与 Markdown 预览，团队、关于、管理、登录与编辑弹窗、提示和错误。参照财务样板的标题/正文/说明层级，文章正文延用适于长文的行距。表单标签、错误和主操作有明确的视觉顺序。逐一处理 hover、选中、键盘焦点、禁用、只读和空状态。分别以访客和已有授权用户核对入口，手机能找到主题入口和管理入口。在搜索已有内容时从顶栏切换。打开含未保存文字的模态表单后，在另一标签页切换或改变跟随模式的系统配色。核对原页的文字、筛选、滚动和对话框仍在。归档浅深对照和验证结果，提交公共页面适配。
```

### 06　单独适配 Timing 和甘特图

**交付**　计划、执行、比较和编辑界面均能清楚区分任务状态。任务表、时间轴和连线在换肤后仍对齐。

```text
在 Project Station 仓库执行 docs/site-theme-rollout-plan.md 第 06 步，遵守共同约束。检查 src/timing.css、src/timing.ts、src/timing-layout.ts 及当前相关测试，针对工具栏、表头、粘性列、网格、今天线、任务条、里程碑、依赖线、草稿/历史比较、任务抽屉、附件、导入导出弹窗设置两套语义色。处理抽屉等位置强制 color-scheme: dark 的规则。桌面和手机在默认缩放下均维持任务表与时间轴 44px 行高、54px 对齐表头。用标题、组间距、边框和控件改善密度。以含依赖关系的隔离项目验证同步滚动、缩放、展开折叠、拖动、抽屉和表单。记录同一行边界与依赖线端点在切换前后的坐标，当前行、滚动位置及未保存输入应保留。用已有测试核对排期与导出。提交 Timing 适配。
```

### 07　验证发布候选

**交付**　可复查的浏览器验证结果、浅深对照截图、自动化检查结果和候选提交号。

```text
在 Project Station 仓库执行 docs/site-theme-rollout-plan.md 第 07 步，遵守共同约束。运行 pnpm check（或 node --experimental-strip-types scripts/check.ts）。使用隔离预览和已有 scripts/verify-finance-workbench-browser.mjs。按现有 FINANCE_REVIEW_CASE 约定提供本地案例。把 .fin-sections 固定 rgb(29, 30, 35) 的断言扩展为显式深色、浅色各自的预期背景，同时校验可见内容与图表重绘。覆盖 1440×960、390×844 和至少一个平板宽度。另在 200% 浏览器缩放下检查导航、表单和宽表。逐项复核本计划的视觉定值和六个验收场景，验证主题操作无新增控制台错误、业务请求或页面级横向溢出。记录实际测试数、缺陷及复测、截图路径、待发布提交和回退方法。修复本轮回归后再出候选。反馈本地验证结果，供决定发布时间。
```

**六个验收场景**

| 场景 | 可观察的通过条件 |
| --- | --- |
| 首次进入与刷新 | 清空偏好后分别模拟浅、深系统。直接打开项目财务或 Timing，最早可见帧就用目标底色。显式选择另一主题后刷新，首帧与最终画面一致 |
| 偏好与状态 | 系统切换仅改变跟随模式。手动选择跨路由、刷新及同源标签页生效。禁用存储仍能在当前页操作。切换保留筛选、版本、输入、已打开的面板和业务滚动位置 |
| 财务阅读 | 对照同一批已知数据，读出一个指标的名称、值、币种/单位及期间。在年度表横向追踪同一产品。切换时图例、轴、柱和线同时更新，金额、业务标签和精度一致 |
| Timing 几何 | 核对两侧多行、表头及依赖线。标准缩放下 44px 行、54px 表头保持对齐，切换后仍能从任务追到正确的时间条，手机抽屉保存按钮可达 |
| 可读性与键盘 | 普通文本对比度 ≥4.5:1，大字、关键控件边界和焦点指示 ≥3:1。键盘能选择主题并看见焦点。错误、选中、逾期同时有文字或形状标识 |
| 视口与回归 | 390px 手机和平板可以读完整金额，宽表在自己的容器中滚动。200% 缩放仍可访问操作。项目、文章、管理、财务和 Timing 关键流程及仓库统一检查通过 |

### 08　发布与回退演练

**执行时点**　此段是独立的正式发布指令。第 07 步验收通过、决定上线时再发送。

```text
请正式发布 docs/site-theme-rollout-plan.md 第 07 步验收通过的候选版本，执行第 08 步并遵守 AGENTS.md。先核对候选提交、线上实际运行提交和两者差异，以线上实际版本为回退点。如果两者之间包含与主题无关且尚未验收的改动，先从实际运行基线形成仅含已验收改动的候选，并重新通过第 07 步。使用仓库现有版本化发布流程在隔离环境演练发布与应用回退，核对现用数据目录、附件目录和应用入口。按候选提交发布应用，保留现用数据库和附件。通过公网检查首页、财务、Timing 深链接及主题资源、浏览器首次加载、切换和刷新。授权业务写入继续使用隔离环境验证。遇到资源缺失、登录失效或主题交互阻断，回切先前实际运行的应用版本，复查入口与数据目录。记录发布时间、前后提交、验证结果及回退点，按仓库规则提交发布记录。
```
