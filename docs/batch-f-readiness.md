# Batch F 开工准备与 F0 口径确认

2026-11-16。本文件是 E 之后的需求准备材料；用户已确认首期为**项目预算、实际成本明细、分类汇总**。币种、税口径、录入/确认与更正规则按用户回复“后续根据实际项目填入”保留待项目口径，不用示例替代确认。没有新增财务表、接口或业务写入。E 的验收证据与未部署边界见 [E 汇总](batch-e-validation.md)。

## 1. F0 需要作出的业务选择

建议用一份真实项目的脱敏样例逐项确认，下列选项是可讨论的首期边界：

| 决策 | 建议起点（待用户确认） | 需要确认的差异 |
| --- | --- | --- |
| 首期范围（用户已确认） | 项目预算与实际成本明细、分类汇总 | 采购、发票、付款、收入/利润未纳入本次确认；后续扩展另定，成本与付款不能默认等同 |
| 记账口径 | 每条明细有发生日期、类别、金额、说明、证据及状态 | 按发生/验收、发票还是支付认定实际成本；跨期、退款、冲销如何计入 |
| 币种 | 先在一个项目样例中使用单币种 | 是否允许混币种；本位币、汇率来源/日期、汇兑差额、金额与单价精度 |
| 税 | 明确每项金额为含税或未税，再定义汇总 | 税率、可抵扣税、不同税率、四舍五入层级；不能默认为所有税都计入成本 |
| 流程 | 区分草稿与已确认，已确认的更正留痕 | 谁审批、能否自审、退回/撤回、已付或关账后的更正规则 |
| 权限 | 财务查看/录入/审批/导出分别授权 | 系统管理员的财务权限；项目经理/成员可见范围；是否按类别限制 |
| 报表 | 预算、已确认成本及差额按类别展示 | 未确认成本、采购承诺、未付款、现金流、收入利润是否首期纳入 |
| 历史与保留 | 已确认记录不可无痕覆盖 | 留存期限、附件替换、软删除、冲销、关账和重新打开的审计规则 |

已确认范围如上；用户明确要求币种/税、录入/确认及更正规则后续按实际项目填入。进入该项目的 F1 业务实现前，把项目口径、金额精度与角色写入决策记录；当前示例只用于核对，不当作默认规则，也不反复要求用户现在补齐已选择后置的信息。

## 2. 可核对的项目样例

以下**仅为 F0 讨论示例**：单币种 CNY、金额展示2位小数，假设“已确认费用”作为成本口径，暂不涉及税/汇率。该假设未自动成为产品规则。

| 预算类别 | 示例批准预算 |
| --- | ---: |
| 设计/样件 | 60,000.00 |
| 测试验证 | 25,000.00 |
| 预备金 | 15,000.00 |
| 合计 | 100,000.00 |

| 示例明细 | 类别 | 状态 | 金额 | 汇总处理 |
| --- | --- | --- | ---: | --- |
| 样件费用 | 设计/样件 | 已确认 | 12,000.10 | 计入成本 |
| 测试服务 | 测试验证 | 已确认 | 3,500.25 | 计入成本 |
| 对测试费用的明确更正 | 测试验证 | 已确认 | -500.00 | 关联原记录，保留原值与原因 |
| 待核对费用 | 测试验证 | 草稿 | 2,000.00 | 单独列示，不混入已确认成本 |

按该示例口径，已确认成本为 **15,000.35**，预算差额为 **84,999.65**。支付了多少钱应另有匹配关系和口径，不能直接把此成本合计命名为“已付款”；收入未定义时也不计算利润。F0 需确认业务样例是否符合实际。

## 3. 候选字段与验收例

候选预算字段：稳定项目ID、预算版本/状态、币种、类别、金额、批准人/时间及修改原因。候选成本字段：记录ID、项目ID、类别、发生日期、金额/币种、税口径、说明、对方名称（如需要）、证据附件、状态、修订、创建/确认身份与时间、更正来源。采购/发票/付款/收入仅在 F0 纳入后另行建模，不用同一条费用记录隐式承载所有生命周期。

F0 应形成字段示例和预期结果：

1. 上表三条已确认金额相加必须恰为15,000.35，不出现浮点尾数；草稿2,000.00不进入该合计。
2. 双击创建/确认或响应丢失后重试只产生一条业务效果；并发修改以修订冲突阻止覆盖。
3. 无财务权限的 Timing Editor 不能通过直链、导出或附件接口读取财务数据；撤权在后续读取和提交即时生效。
4. 已确认记录更正可追溯原记录、原因、执行身份及审批过程；关账/审批限制以 F0 定稿为准。
5. 明细、分类小计及总计能逐项核对；输入/显示/导出金额保持一致，导入失败没有部分入账。

## 4. F1 的工程边界

- 独立财务表、API、迁移与项目/稳定用户UUID关联。财务明细和金额不进入公开 `/api/data` 卡片聚合，不添加到 Timing task JSON。
- 金额使用经 F0 确认的定点表示。可选整数最小单位或十进制定点字符串；HTTP 中超安全整数的数值用字符串。不能用二进制浮点累计金额，也不能在未定义币种精度时一律乘100。
- 显式财务能力候选为查看、录入、确认/审批、导出及附件；命名和管理员边界待 F0 确认。复用稳定身份和实时 policy 检查，不自动把项目 Editor 等同财务角色。
- 创建/确认需要独立幂等键和业务回执；修订、权限、状态及审计在同一主线程事务完成。失败不产生部分金额或成功审计。
- 文件计算复用 E2 的有界池、字节/排队/时间限制和取消机制。新增业务任务类型之前定义固定财务快照与 await 后最终授权/修订复查；签名密钥按业务隔离，不直接复用 Timing 工作簿密钥。
- 备份/恢复需纳入全部财务表、证据附件、审计及回执，验证代码与数据配套。E 当前迁移到10；F 开工时核实最新编号后再新增迁移，预计下一编号11，不在准备阶段修改 schema。

## 6. 下一步交付顺序

F0 先形成已确认/暂缓范围、金额/税/币种规则、状态流转和角色矩阵，以及1个脱敏项目的可算对样例。F1 再实施数据/权限和独立回归；F2 完成确认范围的明细与更正流程；F3 做汇总及预览/确认输入输出；F4 验证金额、权限、并发、响应丢失、迁移及恢复。每次重要更新提交 Git，生产推送/部署仍需单独授权。
