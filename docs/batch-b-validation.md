
2. 备份实际耗时 111ms，独立 verify 5ms；记录配套提交、格式、时间、策略待定项、全表及文件证据。

4. restore 写新目录，复制/校验实际 14ms；启动恢复服务并实际登录，Timing 中任务、版本、依赖及附件记录正确，请求项目页面返回 200，下载附件 SHA-256 与原字节相同。恢复命令开始至登录/项目/下载核验共 243ms。

## 失败、修复及未执行项

- 首次 check 的 EACCES 是隔离运行权限问题，获准使用回环后通过。Git 初次写 index.lock 受沙箱只读保护，使用本轮获准的本地提交权限完成；未更改用户文件或推送。
- 实施中的两次失败来自新测试夹具：降回 A 时漏删 B 索引；SQLite 返回对象的 null prototype 与清单 JSON 普通对象不适合深比较。补齐 A 结构、将迁移证据规范为普通对象后通过；没有跳过断言。
- 真实磁盘故障在 Windows 上可返回 ENOENT 而非 ENOTDIR。未创建字节时允许意图直接完成；有字节/隔离失败则保留持久化重试。测试改为核对“无虚假附件登记，残留任务必须有失败次数”，不强行要求一种操作系统错误码。
- 多行 SQL 错误可能伪装 at 调用帧，已先整体剥离 error.name/message 后保留真实帧；新增 canary 实测通过。初始化打印密码也已修复并记录兼容变化。
- 最终实现复核发现仅靠 SQLite 完整性和表摘要不足以拒绝初始化中断/登录凭据结构损坏的库，已新增 initialized/site/可用账号状态检查并实测失败不会留成功恢复点；这属于本批恢复验收，不扩展账号体系。随后用最终提交重新执行独立 CLI 演练通过。
- 没有执行：远程 CI、生产数据/进程/备份恢复、旧部署首次切换的真实停服核验、正式容量/磁盘耗尽/断电/OS 崩溃、Linux 实机演练、多浏览器与移动平台、A 原生离开各分支、生产发布。SIGKILL 是进程级崩溃证据，不代表断电/硬件可靠性认证。
- 生产上线前还须用受控副本核对正式数据结构、旧文件归属及迁移/配套回退，确定执行负责人、备份频率/独立副本与保留/隔离窗口、容量监控及恢复流程。校验和不等于加密或防恶意篡改；运维目录权限仍须部署验收。没有第三方平台接入或保留自动删除。
