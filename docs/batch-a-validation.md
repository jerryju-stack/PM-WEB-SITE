## 复验方法

pnpm check 运行统一自动检查。手工浏览器复验可运行 node --experimental-strip-types scripts/browser-fixture.ts；该脚本自动创建临时数据库，输出 base/direct/项目 ID，使用 tests/http-fixture.ts 的隔离账号。绝不能将这些账号用于部署。浏览器登录后可在两个页面按上表复验。

测试代理的 /__test__/hold 和 /__test__/release 仅存在于 scripts/browser-fixture.ts 创建的代理中，用来暂停/放行本机写入；不属于 server.ts 的应用接口。测试结束需要停止代理和其子服务。截图与浏览器验证本批为人工/工具验收，尚未自动放进 CI，不新增浏览器测试依赖。

## 迁移、兼容与回退

详见 [写入契约](write-contract.md)。001 只新增资源版本字段，初始为 0；任务版本保持原值。旧客户端更新/删除缺版本会收到 409，需刷新；旧 POST-with-id 不会重新创建删除记录。项目 planned date/startDate 属于基础信息，任务日期是另一份排期数据，项目表单不回写任务派生字段。

正式使用前应停写、停止旧服务，备份同一时点的数据库/WAL/SHM（如存在）及 uploads，保留配套代码，在副本验证后再启动新版本自动迁移。本轮只在临时数据上验证，没有操作正式数据。

代码回退与数据恢复必须区分。旧代码即使能读新增列，也不会维护新版本语义；发生新语义写入后，仅 git revert 不安全。需要停写并恢复配套代码及完整数据/附件快照，或另行制定并验证兼容恢复方案，不能承诺快照之后写入自动保留。

尚存范围外风险：创建响应丢失后重试仍无服务端幂等平台；附件崩溃一致性、完整审计/备份、团队权限与实时同步未实现；全量同步排期和 SQLite 写入路径仍需按实际规模评估。本批没有性能提升声明，也未改变暂停和任务转父级的业务规则。
