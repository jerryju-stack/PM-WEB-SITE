## 4. Batch D：Timing Plan 版本历史

### D0：已有交互签收与创建重试保护

**交付：**补齐 A 的原生舍弃、刷新、关闭页面确认/取消及断网重试验收。为现有项目、文章及附件上传等确有重试风险的创建入口制定并实现幂等合同，保留业务写入与结果登记的事务一致性。范围按入口分提交，不做通用事件平台。

幂等键限定用户稳定身份、项目/资源范围和操作类型；同键同内容重试返回原结果，同键不同内容拒绝。读取原结果前仍检查当前权限。明确键保留期与过期后的处理，不承诺无限期防重；附件重试还要处理重复字节和 B 清理任务。新功能有类似创建时直接复用这套合同。

**验收：**双击、并发同键、服务端成功但响应丢失后的重试只形成一个对象；不同内容同键失败且不写入；撤权后不能靠旧键取得私有内容；原生离开路径分别记录真实浏览器结果。

**回退：**优先关闭新创建入口或恢复兼容代码，不移除已生成的幂等记录来掩盖重复。D0 不重新证明或重做已完成的 A–C。

### D1：自动保存历史快照与只读历史页

**PM 场景：**任务日期、工期、依赖或责任人多次改变后，能够回答“谁在何时把什么改成了什么”，并打开当时整份计划。

建议区分三种标识：

| 标识 | 用途 | 规则 |
| --- | --- | --- |
| 当前任务 revision（r） | 检查并发旧写 | 继续沿用 A 的合同，不倒退、不复用，不拿项目基础 version 代替 |
| 历史快照 ID | 定位某次已提交计划 | 每次成功提交 Timing 变更时，在同一事务保存不可变快照及元信息；失败/409 不产生成功历史 |
| PM 正式版本（V1/V2…） | 标记评审、客户要求或里程碑所采用的计划 | D2 引入，指向一个确定快照；普通保存不自动生成新的正式 V 版本 |

**快照内容：**稳定项目/任务 ID，任务层级与排序、名称、负责人身份及当时显示名、开始/结束/工期、进度、里程碑、依赖、备注、阶段与项目排期汇总；保存当时用于呈现的项目名称及排期规则/schema 版本。记录操作人 UUID/显示名快照、服务端时间、来源 revision、操作类型和可用的变更原因。项目元信息单独修改不会伪装成 Timing 变更，其来源资源版本随快照记录。

**读取规则：**展示快照中已存的日期和汇总，不用新排期算法重新计算历史。任务删除后仍可在旧快照查看；人员更名/删除不破坏旧显示。引用旧用户身份仅用于追溯，不恢复其账号权限。初期可采用完整快照，先测量规模再决定压缩，避免依赖无法完整回放的摘要审计。

**旧数据起点：**升级时为每个现有项目保存一份“历史追踪启用时的当前计划”，保留原 revision，记录真实采集时间，不能标为项目最初计划或补造过往版本。后续历史从此点开始；已有备份或外部 Excel 不自动拼成可信历史。

**页面：**Timing 增加“当前计划 / 历史版本”入口；历史列表显示时间、操作者、修订号、变更摘要。历史模式有明显只读标识，可查看表格与甘特图并回到当前计划，不出现误导性的直接保存控件。写入路径与快照生成入口统一，覆盖拖动、依赖顺延、任务增删、批量改动和后续模板初始化。

**附件边界：**本批可保存附件名称/ID 的历史引用，不默认复制永久二进制。附件删除后显示“附件已删除/不可用”，不能以快照中的路径绕过当前下载授权。历史不含账号密码、会话、项目成员列表或财务内容。

**验收：**连续三次成功改期可分别打开三个完整结果；多任务顺延属于一次提交的一份一致快照；事务中途失败时数据、revision、快照、审计一起回滚；并发仅成功者留下新历史；旧快照重启后不变；新历史进入备份/恢复摘要，恢复后数量、内容和权限正确。

**回退：**关闭历史入口时仍保留历史表；若旧代码不再记录新变更，必须暂停 Timing 写入或使用仍兼容历史写入的版本，不能悄悄制造历史缺口。历史删除/自动清理本批不提供，保留与容量策略在上线前明确。

### D2：正式版本、基线和差异比较

**交付：**PM/获授权管理者将一个已保存快照标记为正式 V1、V2 等，填写版本名称、修改原因、适用评审/客户要求和发布说明。建议默认仅已有项目管理能力及 admin 可发布或调整基线，普通 Timing 编辑者可保存工作计划但不自动取得发布权。

首次选定的比较基线必须由 PM 显式标记。新的正式版本生成后，原基线不被自动替换；重新选基线保留操作者、原因、旧/新引用。正式版本内容不可覆盖，订正用新版本并关联被替代版本。发布时检查当前 revision，避免 PM 在旧页面误发布成“最新计划”；编号分配及发布请求支持并发与幂等。

**比较：**支持任意两个历史版本、当前计划与指定版本、当前计划与基线。按稳定任务 ID 对齐，区分新增、删除、字段修改、层级移动、排序与依赖变化。显示旧值/新值、开始/完成日期差、里程碑偏移，并区分直接编辑和排期派生变化。日期差默认明确标为“自然日”，如增加工作日差必须使用已确认日历；未排期与有日期之间的变化不用 0 天误导。

**示例：**V1 中试制结束 11 月 10 日，V2 改为 11 月 13 日，比较页显示“完成日期延后 3 个自然日”、修改人、时间及“试验资源延期”原因；被删除任务仍列在 V1 一侧，同名新任务不视为原任务。示例日期和原因仅用于说明。

**权限：**历史、比较、正式版本、基线及后续导出均使用项目当前 Timing 读取策略。默认“有效登录可读”与“项目成员可读”的现有可配置差别继续保留；移出项目后能否读取按该项目当前策略判断，不能一概宣称所有历史均不可见。比较两个对象必须都获授权，列表计数和错误也不能泄露其他项目。

**验收：**PM 能在历史页找到 V1/V2 并比较；基线与最新正式版可同时辨认；同名/删除/移动任务比较正确；发布冲突和重复请求不生成重复 V 编号；切换为仅成员后非成员旧链接及历史导出被拒绝；正式版与快照内容一致。

**回退：**隐藏正式版本/比较入口，保留快照及发布记录，不删除或重编号已发布版本。

### D3：从历史生成新草稿（可选，D1/D2 可先上线）

将选定历史作为新计划草稿，先展示相对于当前计划的覆盖、增删、依赖和里程碑变化，明确确认后按当前 revision 提交。并发变化返回冲突并保留草稿。成功形成新的修订和历史记录，不倒退 revision，不覆盖原历史。

上线前确定已删任务的恢复 ID/来源映射和当前负责人失效的处理。默认不恢复历史账号、权限、附件字节，也不默认回退当前实际进度/执行备注；哪些字段允许恢复须在界面列出并确认。按当前排期规则校验，不能把旧快照直接覆盖正式数据库。

**验收/回退：**明确证明旧历史和新修订均保留、当前权限有效、关联未悬空、冲突不写入；关闭恢复入口即可停用该功能，保留已完成的新修订。

### E1：8D 数据结构、编辑和旧知识兼容

**交付：**独立的报告、团队、分步骤内容、原因/Why 链、行动清单与文档清单模型；包含服务端校验、项目归属、草稿/处理中状态、筛选和详情页。D1–D8 各区可以保存未完成草稿，必填闭环条件在提交审核时检查。报告级版本先复用 A 的冲突模式，冲突保留草稿，不在首版实现多人逐字段合并。

旧 Lesson Learn 保留原 ID、正文、链接、归属、可见性和历史版本语义，标识为“旧知识记录”。显式“转为 8D 草稿”只映射有依据的内容，保留来源；不自动生成根因、有效性、审核签字或“已关闭”状态。重复转换不得产生多个意外副本，旧条目与新报告之间可追溯。

新 8D 建议默认关联项目并采用明确项目授权；没有项目的历史全站知识继续兼容。新完整报告含客户、零件、电话和失效证据，不因旧知识默认公开而自动公开。公开经验应在 E3 以单独审阅的脱敏摘要发布。

行动责任人/到期日可在报告内部跟踪，允许关联已有 Timing 任务和 D2 正式计划版本；关联本身不改 Timing。以后如需“一键创建 Timing 任务”，须独立验证 Timing 写能力、幂等与任务归属，不因用户可编辑 8D 就授予其改排期权限。

**验收：**PPT 每项字段有明确落点；一份未完成报告可保存并继续；旧文章链接和访问规则不回退；旧记录转换不丢原文、不捏造完成状态；多用户修改有冲突保护；Engineering 能编辑获授权报告但不能改 Timing。

**回退：**关闭新建 8D，保留旧知识读取及已写新数据；旧文章不做不可逆批量替换。

### E2：图片、证据附件和归档引用

**交付：**D2 问题图片、D4 分析/验证证据、D6 实施证据、D7 文件更新附件。复用 B 的文件登记、清理/隔离和恢复流程，新增报告/步骤/行动到附件的明确归属。显示上传人、时间、说明和校验信息；图片使用授权端点，不落公开静态目录。

允许的图片类型、数量、单文件和单报告上限在开发前定义；沿用现有附件限额时也需显式说明。服务端核验类型与大小，处理伪扩展名、脚本内容、路径越界和无权直接链接。缩略图与原图执行相同可见性及生命周期规则。

已审核报告引用的证据需要冻结引用和保留字节，不能在底层附件清理时悄悄删掉；草稿删除、被替换文件和正式归档文件分别定义保留规则。该规则不同于 D1 的“历史附件引用可能失效”，实施时不可混用。

**验收：**图文可重读、直接图片地址和缩略图不能绕过权限；上传/提交中途撤权拒绝登记；失败可重试且无重复；隔离恢复后图文与关联一致；归档引用阻止非预期清理。

**回退：**关闭上传/预览入口，保留已登记文件与授权下载；数据库、原图和缩略图随成套恢复处理。

### E3：审核、关闭、重开和经验发布

建议状态：草稿 → 处理中 → 待审核 → 已关闭；退回后继续处理；重开必须写原因。D1–D8 内容阶段与报告整体状态分开，不用填写百分比代替有效性确认。

**交付：**按步骤检查负责人、措施、期限、验证结果和必要证据；明确不适用项及理由；审核人记录确认/退回理由；关闭时冻结报告版本、行动和证据，修改通过重开形成新版本并保留旧归档。普通编辑、提交审核、关闭/重开、公开摘要发布分别授权。PPT 中 PL Manager 的 Sponsor/审批职责只作为角色设计参考，不自动映射成所有项目 Manager 均可签字。

建议默认 Engineering 可编辑/提交，项目指定审核人或 admin 审核关闭；是否允许自审由业务确认。关闭前所有必需行动完成且验证通过，例外必须有明确批准记录。首页可查看本人行动、逾期项、步骤状态；站内提醒可先做，邮件/外部消息不作为默认已授权功能。

**经验复用：**D8 提炼失败模式、根因、有效措施、适用产品/过程和检索标签。公开发布只复制明确选定并审核的摘要，不自动带出电话、客户信息或图片；原完整报告仍按项目权限读取。摘要关联关闭版本，重开不改写已发布历史，需显示更新状态或重新审核。

**验收：**从问题建立到围堵、根因验证、永久措施、预防、审核关闭走完一份报告；越权关闭/公开失败；缺少必需验证不能关闭；重开不覆盖旧版；公开搜索无私有字段；B 成套恢复后归档及证据可验证。

**回退：**禁用审核/公开入口，保留只读归档；已公开信息不能靠关闭按钮承诺收回已下载副本。
