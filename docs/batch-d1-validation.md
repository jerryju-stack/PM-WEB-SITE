## 实现与兼容边界

| 范围 | 已实施 |
| --- | --- |
| 数据存储 | 新增迁移 005 `timing_plan_versions` 和独立 `timing_versions` 表；每条保存完整计划、版本类型/名称/原因、保存时间、保存人永久 UID/当时显示名、来源任务修订和项目版本 |
| 三类版本 | 基线、自动编号的 V1/V2/V3 序列、最终版本；每次明确保存创建独立记录。允许再次明确保存新的基线或最终版本，保留此前记录，不覆盖 |
| 计划快照 | 保存项目元数据、稳定任务 ID、全部任务字段、父子层级/顺序、依赖、日期/工期/进度/状态/备注，以及快照格式号、当时工作周和排期规则标识；读取旧版本不调用排期计算器 |
| 普通保存 | 沿用现有 `saveTasks` / `writeTasks`；修订增长和联动计算保持原机制，保留版本数量不变。保存版本本身不增加当前任务修订 |
| 只读 | 没有历史更新、删除或恢复接口；HTTP 修改历史返回 405，数据库 UPDATE 触发器拒绝覆盖。项目整体删除仍按现有项目生命周期级联处理版本记录 |
| 并发与重试 | 在同一事务内核对任务 revision 和项目 version、分配 V 序号、写入快照与审计；同一请求标识及内容重试返回原记录，复用标识提交不同内容返回 409；审计失败整笔回滚 |
| 页面入口 | Timing 标题下提供简洁的“当前计划 / 版本管理”入口；展开后保存三类版本、查看保存人/时间/原因、打开历史任务表与甘特图、返回当前计划 |
| 比较 | 支持历史↔历史、当前↔历史；按稳定任务 ID 匹配，展示任务增删、名称、日期、工期、负责人、依赖、类型/里程碑、层级/WBS/顺序，并补充进度、状态、备注及项目信息变化 |
| 草稿与冲突 | 任务抽屉增加“查看版本（保留草稿）”；历史浏览不把当前草稿写进快照，也不覆盖草稿。版本保存冲突保留名称/原因，须显式刷新核对后再次保存 |
| 现有工具兼容 | 既有数据检查/快照清单识别迁移 005 和新增版本表；旧版本格式继续识别。仅做必要兼容接入，没有进行灾难恢复或容量演练 |

附件字节及其可变列表不属于本次计划版本快照；历史页面明确提示回到当前计划查看附件，不混用当前附件冒充历史附件。

### 接口

| 方法 / 路径 | 用途 |
| --- | --- |
| `GET /api/projects/:id/timing/versions` | 版本元数据列表，不读取全部快照正文 |
| `POST /api/projects/:id/timing/versions` | 从服务器当前已保存计划创建基线、V 序列或最终版本 |
| `GET /api/projects/:id/timing/versions/:versionId` | 返回只读元数据和完整计划快照，版本必须属于该项目 |
| `GET /api/projects/:id/timing/compare?from=…&to=…` | 来源/目标可用保存版本 ID 或 `current`，返回摘要及字段前后值 |

日期偏移口径：**目标日期 − 来源日期，按 UTC 日历日计算**；正数延后、负数提前，不把周末排除在日期偏移之外。任一端未排期时不输出数值偏移。工期显示保存时的工作日数，不按日期偏移反推。层级比较包括父任务、顺序、WBS 和祖先路径；新增任务造成 WBS 变化时也会显示。比较“当前计划”读取服务器已保存数据，不包含本地草稿。

类型检查 `node node_modules/typescript/bin/tsc --noEmit`、Git 差异空白检查通过。以下直接相关测试 **33/33 通过，0 失败、0 跳过**：

主要断言：

- 迁移 005 中途故障回滚表和标记；重试/重复应用稳定，已有任务及修订不变，无自动历史。旧 SQLite/JSON 升级及 A/B/C 相关迁移夹具按新增迁移更新后通过。
- 快照保存原始已计算任务和项目信息，当前任务修改/删除及项目改名后历史仍相同，数据库重开仍保留；保存人、时间、规则信息完整；UPDATE 覆盖被拒绝。新增表进入现有数据检查摘要。
- 任务 revision 或项目 version 不一致返回 409；无效类型、空原因、缺失修订被拒绝；相同请求重试不重复创建，改内容复用请求标识被拒绝；V 序号连续，最终版本不覆盖先前记录。注入版本审计失败时快照/序号分配一并回滚，重试正常。
- 同名不同 ID 的任务按新增/删除处理；相同 ID 的日期、工期、负责人、依赖、层级、里程碑等逐项比较；周五→周一偏移为 +3 日历天，反向为 −3；未排期不计算偏移；单纯重排依赖数组不产生误报。
- 真实 HTTP 覆盖保存/幂等、普通保存不增加历史、历史只读、两个历史版本及当前计划比较、跨项目历史 ID 拒绝、访客拒绝、只读账号可读但不能保存、项目收紧成员权限后列表/比较被拒绝。
- 原有排期联动、工作日、精确权重、草稿与乱序读取，以及项目/任务 HTTP 并发合同检查通过。

最初沙箱内 HTTP 检查出现本机回环 `EACCES`；经工具允许的隔离执行路径重跑后全部通过，没有跳过或删除断言。没有开展全站安全审查、灾难恢复演练、容量测试或全量回归。

## 页面使用方法

1. 进入项目 **Timing**，完成普通任务保存。点击标题下的 **版本管理**。
2. 在版本类型选择 **基线**、**V 序列（自动编号）** 或 **最终版本**，填写版本名称、修改原因，点击 **保存版本**。V 类型在项目内自动分配 V1、V2 等编号；自定义名称与编号同时保留。
3. 在版本列表点击 **任务表与甘特图**，页面切到该历史版本，只读查看任务或甘特图；点击 **返回当前计划** 继续编辑。
4. 在比较区分别选择 **来源** 和 **目标**，可任选两个保留版本，或一个保留版本与当前计划，点击 **比较计划** 查看摘要及变化明细。
5. 任务尚有草稿时，可在任务详情中点击 **查看版本（保留草稿）**。回到当前计划会恢复草稿；未切换历史时也可点击 **返回任务草稿** 继续。先保存草稿，才能保存完整计划版本。
6. 保存版本发生冲突时，名称和原因保留。点击 **刷新当前计划以核对**，核对最新任务表和版本信息后再点 **保存版本**，不会自动把旧提交无提示地套用到新计划。
