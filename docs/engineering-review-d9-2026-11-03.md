## 3. 审查发现（按优先级）

P1：可能造成用户未保存输入丢失，E 阶段首先修复。P2：交互正确性、可用性或容量问题，在进入 F 前按下述验收闭环。没有证据将本次发现标为生产数据损坏或 P0 故障。

### R1 / P1：保存失败后退出、重入会清掉本地未保存输入

**位置：** `src/timing.ts:105–109`、`:191–195`、`:206–214`；丢失租约路径 `:181–185`。

`exitEditing()` 等待 `flushInputs()` 却忽略其 false 结果，仍清空 token、释放占用并重新读取；历史切换的 `showPlan()` 同样忽略保存失败。断网/409 后 `loseSession()` 保留输入，但再次点击“编辑计划”，`enterEditing()` 在没有旧租约时跳过 flush，并直接执行 `pendingInline.clear()` 与 `setEdit(undefined)`。用户按提示重新进入后，未送达服务器的输入消失。

**复现证据：** 从当前源文件提取实际函数，注入“保存返回 false”和“重入成功”的依赖：退出仍调用 `release`/`reload`；重入将 1 项 pending 输入清为 0，脏草稿不再存在。它是控制流复现，不冒充浏览器端到端测试。

**E1 修复：** 统一离开/历史切换/重入的状态转换；flush 失败应停止普通离开；租约失效后保留独立恢复副本，重新授权并读取最新数据后让用户比较、明确恢复或放弃，禁止自动重放。撤权时保留输入不代表允许继续写入。

**验收：** 行内和抽屉分别覆盖断网、HTTP 400/409、权限撤销、无效表单、退出/历史切换/重入；失败不清本地值、不误报保存成功，显式放弃才清除；成功恢复仍通过新租约及最新修订校验。

### R2 / P2：Escape 没有等待异步离开检查

**位置：** `src/timing.ts:272–277`、`:447`。

`leaveEditor()` 是 async，键盘处理器却使用 `if(!leaveEditor())`。Promise 为真值，无法阻止后续 `selected=null; render()`。在保存未完成或拒绝离开时，仍改变选择并重绘；不能断言每次都会关掉抽屉，因为抽屉也可能从 `edit.value` 渲染，但“拒绝离开”的控制契约确定被绕过。

**证据：** 注入 `leaveEditor=async()=>false`，执行实际 Escape 处理器，仍得到 `selected=null` 且发生一次 render。

**E1 修复与验收：** 键盘处理器正确 await，并统一忙碌/失败路径；保存未决或返回 false 时不改变选择、输入、焦点或关闭状态；成功时只完成一次关闭。加入真实浏览器的键盘回归。

### R3 / P2：文件生成占用请求主线程，影响其他请求及租约心跳

**位置：** `server.ts:111–117`，`lib/timing-io.ts:21–25`，`lib/timing-xml.ts:9–14`，`lib/timing-pdf.ts:6–58`。

HTTP 请求直接运行 Excel 公式/压缩、XML 解析与 PDF 排版；`zipSync/unzipSync` 和大部分 PDF 计算都是同步工作。PDF 函数标为 async 并不让 CPU 计算离开事件循环。文件路由没有独立的并发预算、任务超时或队列上限。现有大小限制有价值，但不等于响应延迟有界。

**本机证据：** 100 个简单任务的首次 Excel 导出约 562 ms，同进程的 0 ms 定时器延迟约 562 ms；PDF 约 69 ms。是 Windows / Node 24.22.1 的单次冷路径样本，不能当作生产 P95，也未证明生产发生过 30 秒租约超时。连续或更复杂的处理会竞争同一个请求线程，这是代码层面的可用性风险。

**E2 修复：** 先建立导入导出任务/内存/时间预算；把已确认昂贵的纯文件计算移至有界 worker 池，主线程保留最新授权、草稿修订检查和事务提交。导出用固定快照，完成后重新检查权限；超时、取消及队列满有明确反馈，不允许无界创建 worker。运行时脚本每次请求 `stripTypeScriptTypes`（`server.ts:225`）可按发布版本缓存，作为低优先级优化。

**验收：** 100 项 Excel、1000 项 XML、PDF 长名称/深层级/长日期范围；同时发起文件请求和草稿心跳，记录事件循环延迟、心跳往返、耗时和峰值内存；超时无部分写入，重试不重复采用。E0 先登记测试环境和目标，再据此验收。

### R4 / P2：历史列表读取所有快照并逐条查删除状态，采用又重复比较历史

**位置：** `lib/timing-versions.ts:84`、`:89–96`；`lib/timing-drafts.ts:104–106`。

列表使用 `SELECT v.*` / `SELECT *`，将包含完整任务的 snapshot 读入内存，最后才丢弃；每个版本额外执行 `isDeleted()`，且没有分页。采用时先取全部列表，再逐个 `get()`、解析和比较，直到找到等同执行计划的记录；最坏情况遍历全部历史，发生在写事务回调中。

**证据：** 内存 SQLite 的 100 个版本 × 每版 100 个任务，仅取列表就执行 102 次 prepare/query 调用，读取约 2,272,600 字节 snapshot，返回结果却只需元数据。此样本耗时约 3.7 ms，尚不能说当前小库已慢；数据读取和查询放大确定存在。

**E3 修复：** 只选元数据，通过 SQL 排除软删除并分页；补充必要索引；以执行修订/内容指纹缩小“是否已归档”候选，保留最终等价判断及软删除语义，避免通过删除旧版本来掩盖问题。

**验收：** 100/1000 版本样本；列表查询次数不随返回版本数逐条增加，列表不读取 snapshot；采用事务耗时有前后对比；基线、来源、回执、软删除/撤销及 V 编号不回退。

### R5 / P2：排期、层级和页面渲染反复全量扫描

**位置：** `lib/schedule.ts:60–116`，`lib/timing-workbook.ts:13–16`，`lib/timing-versions.ts:89–96`，`lib/timing-io.ts:35–82`，`src/timing.ts:120`、`:299–319`，`lib/database.ts:59–88`。

父子遍历反复 `tasks.filter()`；导入每行过滤子项/同级项并查找旧任务；保存对每个任务重复 prepare 和查旧数组；前端重建整页 HTML、重新绑定控件。多处至少存在平方级扫描。D9 放宽到 1000 项后，更容易叠加在比较、导入和交互路径上。

**证据：** 简单无依赖样本，预热后 5 次 schedule 中位数：100 项 0.81 ms、500 项 5.49 ms、1000 项 10.03 ms。说明当前简单排期计算仍快，不能仅凭循环结构声称网站已卡顿；复杂依赖、长工期和浏览器 DOM 成本尚未压测。

**E4 修复：** 单次操作预构建 `byId`、`childrenByParent`、兄弟排序/WBS 索引；复用 prepared statements；仅更新受影响的页面区域。是否引入表格虚拟化由 1000 项浏览器测量决定，不做无证据的大规模重写。提取租约/自动保存状态机与有类型的接口响应，优先降低 `src/timing.ts` 的变更风险。

**验收：** 100/500/1000 项、20 层、扇出/链式依赖及长工期，比较结果与旧排期完全一致；记录输入到渲染、保存和导入耗时；不丢焦点、滚动位置、未保存值及附件入口。

### R6 / P2：首页数据接口全量读取正文，权限计算重复查询

**位置：** `server.ts:97`，`lib/database.ts:30`，`lib/policy.ts:10–24`。

`GET /api/data` 每次读取全部项目和文章 JSON，再在 JS 过滤权限；对项目的各项能力逐一查询账号/成员/组，文章返回完整正文；admin 还取全体用户。没有分页或摘要接口。权限过滤已经存在，本项是读放大，不是已证实的未授权泄露。8D 与财务数据增长后，不应沿用同样的全站聚合模式。

**E3 修复：** 首页只返回卡片/文章摘要，正文和管理账号列表按需分页；单请求复用权限上下文；跨请求缓存必须正确失效，不能削弱撤权即时生效。

**验收：** 用固定数量卡片分页比较响应字节数、SQL 次数和延迟；公开/成员限定、viewer、admin 与中途撤权的现有用例保持通过。财务明细永不进入公开首页数据接口。

### R7 / P2：新增跨格式边界和恢复交互缺少完整验收，主说明滞后

**位置：** `tests/timing-drafts.test.ts`、`tests/timing-fit.test.ts`、`tests/timing-transfer.test.ts`、`docs/batch-d9-validation.md`、旧 `README.md`/`docs/engineering-review.md`。

旧主文档仍写 D1–D3 部署及“导入直接更新当前计划”，与 D8 不符。本轮修正文档漂移；互操作、PDF 深层级和浏览器恢复仍归 E5，不以“全量测试通过”替代实际验收。
