## 首屏六组指标

以下金额单位为元，均取自字典中的同一个虚构项目。A、B 两款产品分别贡献收入 200、100，已批准的全成本分别为 170、106。两者的年度现金流合并为 −100、60、60，折现率为 10%。

| 显示项 | 管理层看到的含义 | 示例 |
|---|---|---|
| 营业收入 | 所选产品、期间在计入年降和已约定的件价摊回后，一共卖了多少钱。 | 200 + 100 = **300.00 元**。 |
| 经营利润及利润率 | 按批准的全成本口径赚了多少钱，每一元收入带来多少经营利润。项目以利润、收入各自合计后相除。 | A 盈利 30，B 亏损 6。合计 **24.00 元、8.00%**。 |
| 净现值 NPV | 各年末现金流折回起算日，再计入当天的投入或回款。 | −100 + 60/1.1 + 60/1.1² = **4.13 元**。 |
| 内部收益率 IRR | 使整条项目现金流净现值为零的年收益率。 | **13.07%**。 |
| 投资回收期 | 从第 0 期算起，累计现金流首次补足缺口要多久。 | 第 1 年末还差 40，第 2 年收 60，故为 **1.67 年**。 |
| 峰值资金需求 | 资金最紧张时的累计缺口有多大，首次出现在何时。 | 累计为 −100、−40、20，峰值 **100.00 元**，首次在 **第 0 期**。 |

卡片取同一稳定键、字典版本、产品范围及数据截止期，列出批准基线、当前预测及差额。编辑预览另列候选值。比率差按百分点、回收期差按年、资金差按带符号金额显示。零收入的利润率返回空值及「分母为零」。完整、经核实的零值、未启用产品、缺数、口径待核对各有状态。

- **商务与材料**　`Vol_SBS_Updated` 的市场车数乘每车用量得到件数，经 `Input` 换为千件。各 Financials 用市场销量加权报价和材料价，分别应用年降、成本降幅及调整因子。BOM 的 AA/AB 保留报价和原币，AC 行落地金额通常已含 M 列用量，各表的 AC 与 AD 求和边界分别保留。AD 的一次性模具费汇入 C517，再随投资分期。
- **制造与人工**　AME 第 31–36 行给出六条线体方案的定员、CT、设备 OEE、共享负荷、新旧线和工装。投产年的工厂小时费率来自 `Hourly Rate`。产品 D590、C594:C601、C640 可复核从人数、工序次数和效率到单件人工的过程。两条 3PGA 线的利用负荷合在 H32，H33 留空。厂费按 `OH-2017` 的产品行取值，`OH` 留作费率版本对照。
- **开发与验证**　DV 的欧洲包 X 与中国增补 AE 分别进入 PM 的 I/J，PV 的中国预算 Y 进入 K。DV 的试验包已含样机与夹具，PV 的 V:X 标注了 DV 已覆盖的认证。市场共享包按原行分配，与 PM 的人工、差旅合并后从元换为千元。四张 Q426 的合计可对回 PM 的 G14、I14、J14、K14。按 SOP 季度分配至 426，扣 427 后进入全成本 210 和增量 284。
- **投资与现金**　产品 294–300 为毛投入，301 扣原 430 行补偿，302 为净投资。原表 342 已取净投资负数。增量存货、应收和带符号应付形成 323 余额，341 只取前后期变动。338–342 合成 343，因而回款、投资、所得税和工程净额均可追到各自的期别。

**经营口径**　全期以四张 P186（收入）、P191（DVP）、P212（全成本 MPBITRI）、P286（增量税前贡献 CBT）为产品控制。原表 MPBITRI 利润率用 Σ212 / Σ186，ROS 另将全成本利润按原表税额调整。Exec Sum 的 93/106 核对经营年美元金额。第 0 期已有工程费用，年均列及经营年的利润合计均不可替代含第 0 期的全期利润。网站经营利润、EBIT、NOPAT、FCFF 和 ROIC 的财务边界仍待确认。历史值按字典中的 CQA/CEA 专名呈现。

## 合并现金流与数值规则

1. 产品表 D:N 对应原标签 Year 0 及 2019–2028。Year 0 是估值时点，保留该标签。原表没有在此格指定实际付款日期。市场销量输入到 2026 年，后续营运资金释放与零现金流期仍占各自年位。
2. 产品 343 是千 CNY，乘同列 245 行的 USD/CNY 后，349 为千 USD。`Exec Sum `（页名末尾一个空格）的 147–150 行接 349，157 为 OE 汇总，169 为 IC 汇总，177 为项目净现金流，178 为累计。先按同币种同期间合并，再求 IRR、回收期及峰值。
3. 项目历史 NPV 用 `D177 + NPV(C182,E177:N177)`，D 不折现。年有效折现率取 `Exec Sum !C182` 原始小数缓存，逐一对四张产品的 C330 以及分组合计的 C162/C174。实际率随私有对照输出。Input C16 是票据折扣。收益率以 D181、回收期以 D180 为原生控制。峰值与首次期间从 D178:N179 推导。
4. IRR 需同时有流入、流出。负收益率与零收益率均可有效。多次变号须确认解的唯一性，否则报告「唯一性待核对」。网站按未折现现金流首次从负累计回到零或以上作年内插值。全期没有缺口记 0 年，曾有缺口且未回收记「全期未回收」。再次转负保留首次回收值并提示。历史 D180 在期末仍负时给出 `NEVER`，其候选格要求本期严格为正，再取最大候选期。这些异常保留各自口径。
5. 先以源精度换算、汇总及求差，再四舍五入显示。金额用主币单位绝对差 ≤ 0.01（对应千元/千美元 ≤ 0.00001），单价 ≤ 0.000001，比例小数 ≤ 0.00000001，年数 ≤ 0.000001。原期间、归属、件数及首次最低点须一致。千件还原整件时只消除 Excel 序列化尾差（最多 0.0000001 件）。缺缓存或错误须定位原格。D 列无经营量、M302:N302 原表空格等特定模板位置按原求和语义核查，现金行另须有数字缓存。

## 私有依据与重跑

整文件指纹固定输入版本。另以四产品终身合计、收益率、分期现金流以及 Exec Sum 合并结果等 **182 个数值控制格**生成第二个 SHA-256。位置、取值顺序与序列化方式见矩阵的 `controlPin`。对照在本机读取归档公式和保存值，不刷新外链。BOM Components、PM TARIFF 和厂费外链均保留快照身份。原表包含 57 个外链部件，核对结果只证明冻结档案内的关系。

在仓库根目录用 Python 3.10 或更高版本运行，程序只用标准库。本机可直接使用随 Codex 提供的解释器。

```powershell
$py = "$env:USERPROFILE\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe"
$check = ".\docs\validation\project-finance\P01\verify.py"
& $py -X utf8 $check --public
& $py -X utf8 $check
```

第一条核对字典关联、六组虚构数值与异常。第二条从 `CQA_SAMPLE_XLSX` 读取获准的工作簿，也可用 `--search-root` 指定获准的本地搜索目录。显式指定了其他版本、找不到样本、缺少必要缓存或超容差时均以非零退出码结束。默认标准输出可与本次脱敏结果逐项比较。

授权终端使用 `& $py -X utf8 $check --private` 可查看四产品逐年金额及全期合计、原币和报告币现金流、项目实际折现率与回报，以及六条线体设计参数。经营和现金流金额沿用千元或千美元，回报中的 NPV 和峰值使用对应币种的主单位。两种模式都只读取工作簿。
