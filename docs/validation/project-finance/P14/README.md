## 本轮技术验收

- 在网页已有项目卡和一级菜单验证正常入口。管理员逐项打开 CQA 六组指标，归档 MPBITRI 和待签认的标准经营利润分列。十个模块逐项从首页进入，使用有数据的合成项目验证源行、筛选、刷新和返回。三个报表验证预算、回报和版本差异。窄屏另走供应商报价源行的后退、前进和深链刷新。
- 管理员可读取冻结 CQA 并从该版本派生草稿。对冻结版本的写入返回 409，快照和计算摘要一致。业务录入人从主营收卡预览并保存，重开仍显示 21 CNY/件。该会话在降为只读后重试写入立即返回 403，成员移除后读版本返回 404。只读账号只能打开获分配项目，直接访问其他项目或跨项目版本均返回 404。
- 预算录入人与独立审批人使用不同账号完成实际付款、确认、更正和 ETC 更新。自审、并发旧修订、丢失响应的幂等恢复、同会话降权及移除均有断言。质量角色在窄屏回填复测实际，测试所属职责范围。版本比较用已保存草稿验证取消、保存重开和来源往返。
- 逐一打开 85 个实际渲染指标的中文释义，并核对 139 个动态业务、回报、预算及归因契约键。鼠标悬停、键盘 Tab/Escape、触屏点按/关闭分别实测。验收发现悬停时焦点可能位于财务区域之外，修复后 Escape 也能关闭该释义。补齐工位、费用金额、现金和桥归因的中文定义及帮助入口，页面主要标签沿用 P02 决定的英语。

## 备份与恢复

停止所有审核库写入后，执行仓库已批准的备份策略，验证含代码版本和迁移信息的清单，再恢复到同一运行目录下的新 `restored` 数据目录。复核项目、任务、知识条目、用户和权限、财务版本及指针、来源和金额、附件、审计和幂等回执的逐表计数与摘要。对每个财务版本重新计算，核对完整精度、逐期现金、预算和六组关键指标。重启恢复库使用实际登录验证项目隔离、下载字节、源 CQA 计算摘要、T5 时点桥和 T6 审批后账表。本轮 36 张表、18 个财务版本和 1 份附件核对一致。从启动恢复到登录、下载和回报校验共 20.3 秒。配对运行代码为 `3f89b16`。具体计数及时间见 [恢复核验](recovery-checks.json)。

本机入口运行审核恢复副本。当前登录文件根据 `.deploy/finance-p14/latest-run.json` 的 `credentials` 路径定位，凭据、备份、原件数值和真实 CQA 页面明细保存在获准的本机目录。需要重新启动已恢复的审核副本时，可在仓库根目录运行 `node --experimental-strip-types scripts/finance-p14-preview.ts --restored`。

从新隔离副本复跑交接时，先运行以下第一条，再在第二个终端运行其余浏览器、释义和完整检查命令。浏览器脚本会真实写入隔离夹具。停掉第一条启动的站点后运行恢复命令。Windows 中若上次终止留下锁，使用 `data-maintenance.ts unlock --data <审核库目录>` 确认进程已退出并清理锁。备份策略要求运行代码及维护脚本已提交，以便把备份绑定到可复现的 Git 版本。

```powershell
node --experimental-strip-types scripts/finance-p14-preview.ts
node scripts/verify-finance-p14-browser.mjs --workflows
node --experimental-strip-types scripts/verify-finance-p14-glossary.ts
node --experimental-strip-types scripts/check.ts
# 停止隔离站点后运行
node --experimental-strip-types scripts/verify-finance-p14-recovery.ts
```
