# D-5 Excel 导入局部更新

- 确认导入按钮和确认框移至预览操作区。按钮始终显示并可反馈缺失条件；处理中临时禁用。错误在按钮附近显示，预览校验项可跳转到对应 Excel 行。
- 匹配优先使用当前项目的有效签名身份，其次使用 `orderedTasks` 生成的当前项目 WBS；唯一候选自动预选，无候选默认新增，多候选阻断并要求选择。显式选择优先于自动默认值，重新预览保留选择。
- WBS 匹配显示来源；名称不同显示黄色提醒及 Excel / 网站名称，不增加确认门槛。红色校验错误继续阻止预览写入。
- 匹配变更清除确认状态并要求重新预览。确认接口仍只写入服务端已校验的预览快照，并检查项目、操作者、修订、项目版本和有效期；删除、层级、排期及历史版本规则沿用。

验证：`node --experimental-strip-types --test tests/timing-io.test.ts tests/timing-transfer.test.ts`，7 项通过；`tsc --noEmit` 和 `git diff --check` 通过。覆盖身份优先、跨项目身份回退、WBS 默认值、名称差异可写入、默认新增保留原任务、手动选择保留、旧预览拦截、重复映射及原有事务/版本冲突规则。界面通过实际事件处理器和轻量 DOM 桩验证按钮、反馈、选择与预览状态；未做全仓 review 或浏览器视觉验收。HTTP 测试使用本机临时服务，数据库均为临时测试数据。

保留限制：WBS 仍须满足现有层级编号校验；空 WBS 默认匹配为新增，但须补齐有效编号后才能导入。文本 `1.10` 与 `1.1` 保持区分；若 Excel 已将数值单元格 `1.10` 存成 `1.1`，无法恢复丢失的尾零，仍应使用文本编号。当前 `orderedTasks` 生成的项目 WBS 本身唯一，多候选保护分支未通过真实重复 WBS 数据构造验证。本次未部署服务器，未处理 HTTP 访问及保存版本问题。
